数据模型与应用扫描

SQLite 存储架构 · 应用扫描策略 · 图标缓存

SQLite 数据库 Schema
── items (核心树结构) ──────────────
id          INTEGER PRIMARY KEY
uuid        TEXT UNIQUE NOT NULL
type        INTEGER NOT NULL
  1=page, 4=app, 7=group
parent_id   INTEGER → items.id
ordering    INTEGER NOT NULL
  同一 parent 下的排序
created_at  REAL

── apps (应用信息) ─────────────────
item_id     INTEGER → items.id (PK)
title       TEXT NOT NULL
bundle_id   TEXT UNIQUE
store_id    TEXT
category    TEXT
path        TEXT NOT NULL
  /Applications/Safari.app
bookmark    BLOB
  Security-scoped bookmark

── groups (文件夹) ─────────────────
item_id     INTEGER → items.id (PK)
title       TEXT NOT NULL
  用户自定义文件夹名

── image_cache (图标缓存) ──────────
item_id     INTEGER → items.id (PK)
icon_1x     BLOB
icon_2x     BLOB
updated_at  REAL

── schema_version ──────────────────
version     INTEGER NOT NULL
应用扫描流程
AppScanner.scan()
┌──────────────────────────┐
│ 1. 读取扫描目录          │
│    • /Applications       │
│    • ~/Applications      │
│    • /System/Applications│
│                          │
│ 2. 过滤 .app bundles     │
│    • 检查 Info.plist     │
│    • 排除后台服务:        │
│      - 无 CFBundleName   │
│      - LSUIElement=YES   │
│      - 在排除列表中      │
│                          │
│ 3. 提取应用信息          │
│    • title (本地化名)    │
│    • bundleIdentifier    │
│    • icon (NSWorkspace)  │
│    • app path            │
│                          │
│ 4. 与数据库同步          │
│    ┌──────────────────┐  │
│    │ 新 app → INSERT  │  │
│    │ 已有  → UPDATE   │  │
│    │ 已删  → DELETE   │  │
│    └──────────────────┘  │
│                          │
│ 5. 首次: 自动分页       │
│    按 maxPerPage 切分    │
│    追加到末尾页面        │
└──────────────────────────┘

数据模型 Swift 结构

A

struct 值类型（推荐）

用 struct 定义 AppInfo / GroupInfo / PageItem，配合 enum ItemType。轻量、不可变、易于在 CollectionView 的 diffable data source 中使用。

enum ItemType: Int { case page = 1, app = 4, group = 7 }
struct PageItem {
  let id: Int64
  let uuid: String
  let type: ItemType
  let ordering: Int
  var app: AppInfo?   // type == .app 时有值
  var group: GroupInfo? // type == .group 时有值
}
B

class 引用类型

用 class 定义，支持 KVO 和 Objective-C 运行时。更接近原版的 ECSBPageItem 继承体系，但更重。

图标缓存策略

内存缓存 NSCache<NSString, NSImage>，LRU 淘汰，最多 500 个图标。按 bundle_id 缓存，支持 @1x/@2x
磁盘缓存 SQLite image_cache 表存储 PNG 数据。避免每次启动都从 .app bundle 重新提取图标
图标提取 NSWorkspace.shared.icon(forFile:) 获取应用图标。对于缺失图标，使用 NSImage(named: "NSApplicationIcon") 兜底
失效检测 比较 path 的 modification date，变化时重新提取并更新缓存
